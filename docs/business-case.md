# Business case and ownership

## Context

The underlying engagement addressed purchasing-document friction in a custom cabinetry and millwork operation. Material purchasing connects upstream supplier documents with production planning, direct job costs, stock decisions and eventual project-level financial visibility.

## Problem statement

A heterogeneous set of PDFs made repeatable extraction and document organization hard. Manual file handling absorbed time and increased the chance of inconsistent fields, scattered source documents and missing handoff information.

## Design objective

Convert PDFs into structured purchasing data using a workflow simple enough for nontechnical users: place documents in a folder, run a Windows launcher, review one Excel file, and inspect exceptions. Never discard the source documents.

## Value hypothesis vs. demonstrated results

**Demonstrated:** A functional local batch workflow, a structured workbook, supplier folders, confidence-based routing, and a synthetic, reproducible validation set. 

**Hypothesized value:** Less manual administration, better retrieval and traceability, more consistent material data and improved job-costing readiness. These require production measurement and downstream workflow adoption; they are not treated as achieved financial benefits.

## Value engineering measurement framework

Baseline and follow-up measurements should capture manual time per document, exception handling time, percentage of correctly extracted required fields, cost-category acceptance rate and percentage of purchases assigned to jobs. A full ROI model would add volumes, labor cost and operating/maintenance effort.

## Scope boundary

The solution produces **review inputs**, not direct accounting postings. It does not determine final inventory treatment, project margins, or tax and ledger entries. Final decisions belong to business/accounting owners.
